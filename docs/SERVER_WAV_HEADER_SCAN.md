# Bounded server WAV header integration (N50)

The source scanner reads a bounded RIFF/WAVE prefix on the same no-follow regular
file descriptor used for inventory/hash checks. It does not call `wave.open`,
decode audio, reopen a pathname, copy source media, or create a service.

## Independent budgets

`ScanLimits.max_wav_header_bytes` defaults to 65,536 and accepts positive integers
no larger than 65,536. `max_total_wav_header_bytes` defaults to 8 MiB and is a
separate positive aggregate budget. The existing hash and table limits retain
their behavior. A skipped whole-file hash does not prevent a bounded header probe.
The existing CLI remains compatible and uses the new defaults; these two new
limits are configurable through the Python scanner API, not new CLI flags.

WAV handles use unbuffered reads so a small header allowance does not cause hidden
buffered read-ahead. Each header request is at most 8,192 bytes and the remaining
allowance. Nonempty short reads are not EOF. The scanner only marks header EOF
when a read returns empty bytes; it does not consume a sentinel past the cap.
Every successfully returned chunk immediately advances the aggregate counter,
including chunks followed by a read failure. No header read occurs after the
aggregate budget is exhausted.

`coverage.wav_header_bytes_read` is the aggregate count, while
`files[].audio_metadata.header_bytes_read` is the per-file count. Both count
header reads separately from `coverage.hash_bytes_read`; reading the same bytes
once for hashing and again for header inspection counts in each respective
budget. These counters do not claim to measure table reads or all operating
system I/O.

## Projection and provenance

`audio_metadata.header_probe` retains the pure parser's raw declared fields,
status, exact duration basis, inspected-byte count, and issues. The wrapper records
`source=same_descriptor_riff_header`, `scope=header_prefix_only`,
`size_basis=fstat_same_descriptor`, `observed_file_size_bytes`, and
`body_validated=false`. The parser's `provider_size_bytes` input comes from this
same descriptor's `fstat`, not from an audio declaration.

The five existing scalar keys (`frames`, `sample_rate`, `channels`,
`sample_width_bytes`, `duration_seconds`) are emitted only for a consistent
observed header. A duration observation retains the compatible `basis=wav_header`
and adds explicit header-only scope, calculation basis and unvalidated-body status.
A 44-byte file declaring a longer audio body keeps its raw declarations but has
no supported duration, a failed parse, and incomplete coverage. A complete hash
of those 44 actual bytes remains valid independently of the malformed layout.

File parse status is `metadata_only` for observed header declarations, `limited`
for partial headers, `failed` for malformed/size-conflicting or unreadable headers,
and `unsupported` for unsupported layouts. Probe diagnostics enter manifest
issues, including body-not-validated scope, so audio projection does not advertise
complete media validation. A byte-limit warning can coexist with a useful
header-derived duration if all required declarations are already visible.

## Descriptor lifecycle and changes

Enumeration metadata is checked against the first descriptor stat, including
identity, size and modification/change times. A change before reading is explicit.
A final descriptor stat checks the read interval. If the source changes, final
stat fails, or closing the wrapper fails, accepted hash/count and scalar audio
projections are revoked. Raw header declarations remain; any previously assembled
duration observation keeps its raw value with `seconds=null` and an explicit
failure status. `coverage.files_hashed` counts retained complete hashes, not
hash attempts later invalidated.

Descriptor ownership transfers to the file wrapper only after successful
`fdopen`; failure closes the acquired descriptor directly. The wrapper closes on
all later paths. Unchanged stat metadata is not a stable filesystem snapshot or
cryptographic proof of source authenticity. Header inspection does not establish
ASR alignment, intelligibility, recording duration by decoding, or correctness of
unread trailing chunks.

## Validation

`test_wav_scanner_integration.py` uses generated bytes to check legacy scalar
compatibility with separate hash/header scope, truncated declarations, independent
per-file/aggregate budgets, failure accounting, short reads and limit validation.
`test_wav_stream_acceptance.py` independently instruments production scanner I/O,
mutation and descriptor lifecycle. At this integration checkpoint, the combined
owner, stream-acceptance and existing scanner tests passed: **41 tests**. The
coordinator records final full-suite and real subprocess CLI evidence separately.
No private corpus or committed binary fixtures are involved.
