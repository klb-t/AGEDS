# Verified seekable decoder input

`VerifiedReader` in `server/app/verified_reader.py` gives PyAV/faster-whisper a
binary file-like object while retaining the same verified source descriptor.
This is the second concrete use of `verified_media.VerifiedMedia`: HTTP serving
and seekable decoder reads need the same initial content verification and
per-chunk integrity checks. The existing HTTP primitive and public contract are
reused unchanged; no new shared ontology or media-copy format is introduced.

```python
with VerifiedReader(path, expected_sha256, expected_size,
                    store_root=settings.store_dir) as source:
    result = adapter.transcribe(source)
    # Exhaust any lazy segment iterator while this context remains open.
    source.verify_unchanged()
    # Only now may the worker publish, subject to its existing lease fence.
```

The required store root is traversed by no-follow directory descriptors; the
regular source file is opened read-only/nonblocking. Recorded lowercase SHA256
and a known nonnegative byte count are required. Initial verification reads the
full retained descriptor and keeps compact per-chunk SHA256 values. Decoder reads
then verify each full covering chunk before returning its immutable buffer slice.
Pathname replacement does not redirect the descriptor. In-place edits cannot
return altered bytes unless SHA256 collision resistance fails. Raw paths and
file descriptors are not exposed by the file-like API: there is no public `name`
or `path`, and `fileno()` raises `io.UnsupportedOperation`.

This is a trusted Python adapter boundary, not a sandbox against malicious
introspection of private attributes. It is not an authenticity, ASR truth,
physical WORM or filesystem-snapshot claim.

## File-like contract and bounds

`read(size)`, `readinto(buffer)`, `seek(offset, whence)`, `tell()`, `readable()`,
`seekable()`, `writable()` and context-managed `close()` follow binary read-only
semantics. Seeking beyond EOF is allowed up to signed 64-bit position bounds;
negative positions and unsupported origins reject. Reads at EOF return empty
bytes. `readinto` verifies the entire requested result before modifying the
caller buffer, so a changed later chunk leaves that buffer and logical position
unchanged. Calls are serialized with a reentrant lock, including close.

Every read is capped at **1,048,576 bytes**. An explicit request above that cap
fails. `read(-1)`, any negative-size read, `read(None)` and `readall()` return the
entire remaining content only when it fits the cap; otherwise they fail instead
of silently returning partial content. Callers needing more must repeatedly use
bounded reads. `readline()` and `readlines()` are unsupported, avoiding the
inherited unbounded line-aggregation protocol. No media copying or temporary
snapshot is performed.

The reused media primitive retains its **4 GiB** total source limit,
**256 KiB** chunks and at most **16,384** chunk digests (512 KiB digest bytes).
Read aggregation and transient copies are bounded by the 1 MiB read cap plus
chunk-sized buffers. These limits bound this input adapter, not PyAV's decoded
audio allocations or the ASR model's memory use.

An integrity, availability, read-I/O or read-size-limit failure is sticky. Even
if a decoder catches the error and another actor restores the original bytes,
subsequent reads and final verification refuse to certify the run. This prevents
silently publishing a partial decoder result after a swallowed input failure.
Invalid caller argument types and unsupported optional protocols are separate
API errors. Existing `MediaUnavailable`, `MediaIntegrityError` and
`MediaLimitError` exception classes remain the worker's failure boundary.

## Final verification and lifecycle

`verify_unchanged()` rechecks every initial chunk, the full SHA256 and byte count
on the **same descriptor**, without altering logical position or reopening the
pathname. It catches current changes in bytes the decoder never requested and
also honors the sticky failure state. An empty initial file is checked for size
changes. The worker must invoke it after eager decoding or lazy iterator
exhaustion and before its transactional publication/lease check.

Final verification does not make bytes immutable afterward, and cannot prove
that an unread byte was never temporarily changed then restored between checks.
All bytes actually returned to the decoder were verified at the read boundary.
Context-manager exit closes the descriptor on success or exceptions; explicit
close is idempotent. Construction failures and ordinary garbage collection also
release the underlying descriptor. Synchronous preparation, reads and final
verification belong in the worker execution context, not an asynchronous web
event loop.

## Verification evidence

`server/tests/test_verified_reader.py` uses generated bytes to check seek/read
semantics, bounded whole reads, atomic readinto, pathname replacement, unread
in-place mutation, restored-after-error refusal, descriptor/path API exclusion,
context cleanup and absence of pathname reopening. Existing verified-media
HTTP tests remain part of regression coverage.

The installed PyAV 16.1.0 source declares default `buffer_size=32768` in
`av/container/core.pyx`; its `av/container/pyio.pyx` callback invokes the object's
`read(buf_size)`. A direct local PyAV smoke decoded **16,000 samples** from a
one-second synthetic mono 16 kHz PCM WAV through this reader; the reader stayed
open after container close and final verification passed. This used installed
dependencies and generated silence, without downloads. Actual tiny.en inference
and persisted worker verification metadata have their own independent receipt;
the decoder smoke alone is not ASR quality evidence.
