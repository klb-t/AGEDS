## Synthetic cases and findings

- Correct PCM and IEEE-float headers retain the declared duration basis while
  always reporting `coverage=header_prefix_only` and `bodyValidated=false`.
  PCM 8/16/24/32-bit and float 32/64-bit geometries are exercised.
- A data header with uninspected payload yields a header-derived duration only
  when its declarations are consistent; explicit EOF before that payload ends
  suppresses duration. Unknown provider length is not invented. Contradictory
  provider byte counts and negative provider sizes remain visible and suppress
  duration.
- Every truncation length before the complete basic data header, truncated data,
  undersized RIFF extents, incomplete chunk headers and absent required odd-byte
  padding fail without claiming duration or body validation.
- Correct odd-size unknown-chunk padding preserves the following header position;
  missing padding cannot shift arbitrary bytes into a valid fmt/data interpretation.
- Duplicate fmt/data headers visible inside the prefix invalidate the earlier
  duration. Data before fmt is rejected. Duplicate headers that could exist
  beyond an unread data body remain explicitly unknown, not assumed absent.
- Unsupported containers (RIFX/RF64/other forms), codecs, sample widths and fmt
  extensions are not treated as ordinary PCM. An 18-byte fmt with zero extension
  length is accepted; nonzero/unsupported extension layouts are rejected.
- Inconsistent channel/rate/byte-rate/block-alignment values and partial sample
  frames suppress duration. Raw inconsistent scalar declarations remain preserved.
- Maximum unsigned 32-bit RIFF/chunk lengths use non-wrapping Long arithmetic.
  `0xFFFFFFFF + 8` remains `4294967303`; huge chunks cannot wrap into later visible
  headers and manufacture a duration.
- A complete data header ending at exactly byte 65,536 is observable. A header
  crossing that boundary is partial even if more input bytes were supplied.
  Supplying a longer buffer with EOF does not turn the bounded prefix into a
  whole-file observation: bytes inspected stay capped, effective EOF is false,
  the prefix-limit issue is explicit and body validation remains false.
- Input arrays are not modified. All fixtures are generated byte arrays; no
  private recordings, source files, provider permissions or models are involved.

Source review independently confirmed checks precede each basic field read,
chunk offsets advance with checked unsigned values represented as Long, visible
chunk payload/padding must fit the declared RIFF extent, and unseen trailing
chunks are disclosed. No acceptance blocker was found in the reviewed core probe.

## Evidence limits

A declared duration is arithmetic over header declarations, not a measured or
fully validated recording duration. Even a fully supplied small RIFF container
is not decoded and receives no audio-body validation claim. Provider size is a
separate observation; matching it does not prove the provider returned all bytes,
that media decodes correctly, or that timing aligns with spoken content.

The probe inspects at most 65,536 bytes. Prefix limits can leave required chunks,
additional data/fmt chunks and other trailing structure unknown. Unsupported
formats are explicit rather than broadened by guesswork. Scanner byte-budget,
cache serialization, desktop parity and physical SAF behavior have separate
acceptance owners and are not claimed by this core-only result.
