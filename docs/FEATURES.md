# Features and boundaries

AGEDS implements an evidence-review workflow. The source, each acquisition, processing attempt, transcript version and interpretation remain separately addressable.

| Area | Implemented behavior | Boundary |
|---|---|---|
| Source preservation | Ingestion stores content by SHA-256 and retains acquisition context, including repeated ingestion of the same bytes. | Application and filesystem integrity checks do not establish physical WORM, authorship or truth. |
| Communication imports | SMS Backup & Restore XML and WhatsApp text imports retain raw fields and repeated occurrences, with idempotent import positions. | Timezone, date-order and historical provenance ambiguity remain explicit. |
| Transcription | Local faster-whisper worker; atomic claim, renewable lease, recovery and fenced publication; separate run for each attempt and version for each success. | A working synthetic smoke test is not recognition-quality evidence for a personal corpus or language. |
| Review and citations | Browser and Android version selection, annotations, contiguous segment/word citations, pinned quote text and timing; saved-citation range playback. | Word selection requires stored ASR timestamps and consistent text. Citation validation does not verify listening, speaker identity or acoustic alignment. |
| Search and history | Literal SQLite FTS5 search with typed validation and work limits; descending-ID pages and bounded client history. | Completeness describes a bounded query, not the completeness of imported or indexed sources. Continuation cursors do not provide MVCC across requests. |
| Server/local scan | Read-only bounded CSV/TSV, XLS, XLSX and WAV inspection, inventory, conflicts and coverage reporting. | Unsupported formats, damaged files and resource exhaustion remain issues. No formula execution, original correction or automatic ingestion. |
| Android source scan | SAF directory access through the production scan engine, exact URI identity, raw fields, format hypotheses and app-private cache. | XLS is a narrow partial BIFF8 projection; native and server parsers have different policies. Host tests do not execute Android provider/grant behavior. |
| WAV observations | Bounded RIFF/WAVE header declarations and labeled duration projection, with separate source size and complete-stream hash scope. | Header duration is not measured playback or decoded sample validation. Unsupported containers/encodings are explicit. |
| Media reads | Initial whole-file integrity verification and checked descriptor chunks for playback and decoder reads. | Files remain mutable outside AGEDS; limits and platform descriptor requirements apply. |
| Metadata transfer | Package digests and relationship checks; exact canonical import/export through a new inert SQLite archive. | No source media, signature, live restore, replay or job execution. |
| Citation transfer | Bounded version-pinned citation packet with a standalone independent consumer. | Locators are inert and packets are not anonymized. Recorded source hashes cannot be recomputed without source bytes. |
| Source catalog | Collections (device/account/export), read-only recursive scans through ZIP/TAR (7z/RAR behind optional adapters) with virtual locators, byte-signature typing over extensions, content groups by SHA-256 with every observation, filename collisions, coverage with per-basis date ranges and gaps, CSV/XLSX/HTML export, deterministic profiles with optional model descriptions as hypotheses ([catalog](CATALOG.md)). | Scan observations are not acquisitions. 7z/RAR were not executed in this environment. Gaps describe missing records, not inactivity. |
| Import planning | Detectors propose importers for catalogued files and archive members; ambiguous items need a human choice, opt-in importers stay off; approved items run idempotently with collection and locator provenance, verified member materialization outside source roots and resumable runs ([import plan](IMPORT_PLAN.md)). | Files without an importer are listed, not acquired. Tested on synthetic layouts only. |
| AI chat exports | ChatGPT (full `mapping` tree, shards, reasoning parts, attachment references) and Claude.ai (content blocks, branches) with key mappings as versioned data; logical identity across exports reports presence, absence and content variants ([chat importers](IMPORTERS_CHAT.md)). | Absence in an export is "not observed", never deletion. Layouts follow public observations, not vendor specifications. |
| Communications and Takeout | MBOX/EML with child attachments, ICS, VCF contact observations, call logs, configurable billing profiles, recording file-name hypotheses, My Activity, opt-in location and browser history, WhatsApp media, EXIF time observations ([communication importers](IMPORTERS_COMM.md)). | Names and numbers from file names are correlation hypotheses. Alphabetic mail zones are not converted. |
| Common timeline | A versioned display rule chooses among all recorded time candidates and reports basis, precision and an uncertainty interval; undated items are listed separately; transcript segments, swimlanes, density, bookmarks and correlation hypotheses (recording ↔ call, e-mail ↔ chat, same conversation across exports) with reviewed status ([timeline](TIMELINE.md)). | The display choice is a projection, not a corrected time. Correlations are never auto-accepted and carry criteria, not probabilities. |
| Transcription strategies | ASR recipes as hashed data pinned to jobs; a per-segment language strategy restricted to allowed languages (e.g. pl/nl/en) next to the per-file strategy; run comparison; WER/CER benchmark tool; OCR and diarization adapters with candidate-only outputs ([multilingual ASR](MULTILINGUAL_ASR.md)). | Tested with fake engines only: no Whisper, Tesseract or pyannote inference ran here, so nothing is claimed about recognition quality. |
| Time budget | Private category configuration, labelling with visible provenance (human > rule > model hypothesis), sessions, gap model with lower/probable/upper bounds, interval unions without double counting, candles with an always-present unobserved band, sensitivity flags and feature series; stored append-only runs ([time budget](TIME_BUDGET.md)). | An interpretive estimate under recorded parameters, not observed activity. |
| Hypothesis analysis | Preregistered, hash-chained hypothesis versions, evidence dossier with human classification and thesis typology, permutation-based event study with density control and built-in warnings; every result carries a fixed disclaimer label ([hypotheses](HYPOTHESES.md)). | Support material for a human or expert, not a causal conclusion. |
| Reports | Catalog, timeline, time-budget, hypothesis-dossier and lawyer-package reports in HTML (primary), JSON, CSV, XLSX and optional PDF, with a method section, every number traceable to computed JSON, a verifiable manifest and multi-citation bundles; private output directory only ([reports](REPORTS.md)). | Manifests are hashed, not signed. PDF depends on a local Chromium. |
| Read API and ecosystem | Versioned read-only API with local hashed tokens, optional token enforcement and CSRF/host protections; intent executor returning anchored quotes for ChatADHD; annotation proposals requiring human acceptance; Loom graph export with hypothesis quarantine ([read API](READ_API.md), [adapters](ECOSYSTEM_ADAPTERS.md)). | No live ChatADHD or Loom session was executed. Existing routes stay open unless enforcement is enabled. |
| Location history | Google legacy Takeout, Semantic Location History and on-device Timeline exports (Android/iOS) with raw signals, GPX/KML/KMZ/GeoJSON tracks, optional FIT; raw positions vs provider inferences vs user edits kept apart; private places with accuracy-aware local geofences and presence runs; map without external tiles by default; photo geotags matchable against places ([location](LOCATION.md)). | Opt-in per run; a position is a device's or account's, not proof of a person's presence. No real provider export was available. |
| Personal-data exports | Google Photos sidecars and EXIF GPS, Facebook/Messenger (mojibake repaired as a separate layer), Instagram, Telegram, Google Chat, X, LinkedIn, account login activity, document metadata (OOXML/ODF/PDF), Google Keep, local browser profiles (opt-in) ([personal exports](PERSONAL_EXPORTS.md)). | Document authors and sidecar locations are claims; no IP geolocation. |
| Financial, health, transport | Exact-decimal tabular profiles (bank CSV, transit cards, rides), CAMT.053 and MT940 with code-computed balance checks, Apple Health / Google Fit / Samsung / Fitbit behind a health opt-in; sessions and travel segments as provider-inferred durations ([ledger](LEDGER.md)). | Profiles are examples, not vendor specifications; sleep stages and workouts are device inferences. |
| Workbench | Search across layers with epistemic labels, saved searches, bulk tags, folders with pinned references, timeline bookmarks, shortcuts, command palette, light/dark themes and PL/NL/EN interface ([workbench](WORKBENCH.md)). | Interface text only is translated; source text is never altered. |

## Evidence rules

1. Preserve source bytes and source-native metadata.
2. Keep normalized records, parser observations, model output and human annotations separate.
3. Preserve conflicting observations with their locators rather than silently selecting a truth.
4. Attach a citation to the selected transcript version and occurrence.
5. Represent missing provenance and unsupported precision explicitly.
6. Keep deterministic handling of identifiers, dates, numbers, hashes and selectors outside model interpretation.

Transcription currently runs on the server. The Android JNI/whisper.cpp prototype is not wired into the Gradle build or a Kotlin native bridge; it does not provide on-device ASR.

The current service uses SQLite and local content storage. OCR and diarization exist as adapters that report themselves unavailable unless their local engines are installed; they have not been executed with real engines here. The five-layer legal-analysis standard, Live Explainer, signed custody, semantic search and cloud connectors remain future directions; a retained design is not an available capability. All model and provider calls are off by default and require an explicit per-run opt-in that is recorded.
